# Bundled catalogue

What ships in the box: the Ting workflows in `src/ting/workflows` and the built-in
personas in `src/personas/builtin`, one line each, with why it is kept. Items marked
**archived** live in `archive/` and are not shipped (`archive/README.md`).

A bundled workflow pins the exact persona documents it uses, so a persona stays
shipped for as long as any shipped workflow names it. Checked by
`tests/test_catalog_archive.py`.

## Workflows

| Workflow | What it is for | Personas | Status | Why |
|---|---|---|---|---|
| `developer-delivery` | Plan, delegate, verify, integrate, publish, and merge one repository change using durable child workflows and typed evidence. | `developer-coordinator`, `developer-analyst`, `developer-architecture-reviewer`, `developer-correctness-reviewer`, `developer-security-plan-reviewer`, `developer-integration-verifier` | **kept** | Ting delivery subsystem (chart `delivery.*`, `scripts/prepare_delivery_proof.py`, web e2e); parent of three |
| `developer-integration` | Verify and review the complete integration candidate against the approved delivery plan. | `developer-coordinator`, `developer-integration-verifier` | **kept** | child of Developer Delivery; chart `integrationPolicyId` |
| `developer-planning` | Investigate a delivery request and produce an exact-revision plan approved by three independent reviewers. | `developer-analyst`, `developer-architecture-reviewer`, `developer-correctness-reviewer`, `developer-security-plan-reviewer` | **kept** | child of Developer Delivery |
| `developer-workstream` | Implement one isolated work order, run trusted verification, and independently review its immutable candidate. | `developer-coordinator`, `developer-coder`, `developer-code-reviewer`, `developer-security-reviewer`, `developer-adversarial-reviewer` | **kept** | child of Developer Delivery; chart `evidencePolicyId` |
| `research-campaign` | Flexible deep-research workflow that frames a question, explores the evidence deeply through parallel threads, challenges the thesis, and distills durable memory into Mimir. | `research-analyst`, `research-coordinator`, `research-curator`, `research-framer`, `research-publisher`, `research-skeptic`, `research-synthesist` | **kept** | `ting/api/research.py` launches it by name (Research Center) |
| `research-thread-breadth` | Run the breadth explorer over the framed research question and produce a structured finding for the parent research campaign. | `research-explorer-breadth` | **kept** | child of Research Campaign |
| `research-thread-contrarian` | Run the contrarian explorer over the framed research question and produce a structured finding for the parent research campaign. | `research-explorer-contrarian` | **kept** | child of Research Campaign |
| `research-thread-depth` | Run the depth explorer over the framed research question and produce a structured finding for the parent research campaign. | `research-explorer-depth` | **kept** | child of Research Campaign |
| `research-thread` | Run one exploration thread on an assigned angle and produce a structured finding for the parent research campaign. | `research-explorer` | **kept** | child of Research Campaign |
| `reviewed-delivery-flow` | Tracker-driven developer workflow that implements a ticket, iterates through agent review, then waits for a person to approve the merge before it merges the branch and publishes a durable delivery record. | `closer`, `coder`, `publisher`, `reviewer` | **kept** | ticket board + ticket coordinator; delivery with a person gate |
| `saga-planning` | Focused planning workflow that clarifies a brief, drafts a saga breakdown, and pauses for review before publishing the plan. | `saga-brief-framer`, `saga-plan-publisher`, `saga-plan-reviewer`, `saga-planner` | **kept** | `ting/api/sagas.py` and `review_list.py` name it |
| `specification-stack` | End-to-end specification workflow that produces a PRD, SRD, SDD, and delivery breakdown with explicit review and approval gates between each artifact. | `specification-breakdown-critic`, `specification-breakdown-planner`, `specification-framer`, `specification-prd-author`, `specification-prd-critic`, `specification-publisher`, `specification-sdd-author`, `specification-sdd-critic`, `specification-srd-author`, `specification-srd-critic` | **kept** | `ting/api/specs.py` launches it by name (Specs pages) |
| `ticket-planning-flow` | Plans one tracker ticket, has an agent review the plan, then waits for a person to approve it before recording the approved plan for the work that follows. | `ticket-plan-publisher`, `ticket-plan-reviewer`, `ticket-planner` | **kept** | ticket board + ticket coordinator; one of two bundled board workflows |
| `ticket-work-flow` | Does the work one tracker ticket asks for, with or without a repository, then waits for a person to approve the result. | `ticket-worker` | **kept** | ticket board; the only bundled workflow with no repository |
| `tool-skill-builder` | Resident capability workflow that designs, implements, reviews, canaries, and publishes a missing Valkyrie/Ravn tool or skill. | `capability-publisher`, `coder`, `reviewer`, `security-auditor`, `specification-framer` | **kept** | what `build_tool` commissions over A2A (tags tool-builder/skill-builder); 307 runs |
| `code-review-flow` | Tracker-driven developer workflow that implements a ticket, iterates through code review, and merges the branch without publishing a delivery record. | `closer`, `coder`, `reviewer` | **archived** | tests only (catalogue list, one fixture) |
| `infra-change-flow` | Tracker-driven change to a GitOps repository. | `closer`, `coder`, `reviewer` | **archived** | tests only (catalogue list, isolated-branch test) |
| `tracker-delivery-flow` | Tracker-driven developer workflow that implements a ticket, iterates through code review, updates the tracker, merges the branch, and publishes a durable delivery record. | `closer`, `coder`, `publisher`, `reviewer` | **archived** | tests only (catalogue list, one fixture); no infra trigger names it |
