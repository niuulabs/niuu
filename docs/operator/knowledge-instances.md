# Tenant-owned knowledge instances

Operator-configured global services, such as `niuu-shared`, remain available
according to their Guild visibility. Global scope is not offered by the
tenant deployment API; an unowned Flux release is not a global instance.

Deployments requested through Niuu inherit the authenticated caller's tenant.
The request body cannot choose a different tenant. Flux records the owner on
its HelmRelease and uses a tenant-qualified release name, so different tenants
can use the same display name. Listing, inspection, lifecycle actions, and
memory-mount discovery all check that owner.

Ready instances become mounts automatically. Registry descriptors point sessions
and Ting at the authenticated Mimir gateway with a bound mount name. Native
connection credentials are never included in those descriptors. Session workload
identity determines which tenant's mount can be opened.

Mimir instances inherit the deployment host's Envoy JWT profile. Their API and
MCP endpoints enforce the instance tenant, and a NetworkPolicy admits only the
Envoy port. Health probes remain available. An attached warden uses the instance's
own data volume.

gbrain deployments enable `connection.enabled`. At startup, gbrain creates a
native `read,write` token, retains it on the instance volume, and publishes it
to the instance's Helm-managed connection Secret. Its service account can only
read/update that one Secret. The deployment host reads the Secret when opening
an authorized tenant mount; no per-instance Doppler or environment-variable
wiring is required. PostgreSQL credentials remain generated by CloudNativePG.

Legacy HelmReleases without `niuu.world/tenant-id` in their annotations are not
claimed automatically. An operator must verify ownership, assign that annotation
and `niuu.world/instance-name`, and upgrade the chart to enable its connection
and tenant configuration. Instances and persistent volumes are preserved.

## Global Helm releases

Operators can deploy additional global brains through Helm/GitOps and expose
those release names in the target's `global_instances` list. Each release must
also declare the annotation `niuu.world/scope: global`, with no owning tenant
annotation or `niuu.tenantId` value. An explicit global declaration and operator
allowlist are both required; missing ownership alone never grants global access.

These mounts are available to authenticated tenants through the same gateway and
workload-identity descriptors. They are excluded from tenant deployment controls;
upgrades and deletion remain owned by GitOps. Keep Mimir's Envoy JWT protection
enabled and gbrain's native `connection.enabled` credential provisioning enabled.
