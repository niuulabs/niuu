# Niuu vision messy notes

We keep losing the living shape of the idea when the discussion gets handed to
implementation. Niuu is not just an agent platform; call it a Momentum Engine.
The hard part is not starting work, it is preserving momentum through the
ambiguous middle.

Drive is the mechanism behind momentum. It should come from unresolved tension
in resident understanding, not a todo list. Work does not begin with a prompt.
By the time a prompt exists, the idea was already compressed.

Someone said goals, but goals are prompting in disguise. They often smuggle in
the same flattening problem. Reflexes should be learned from experience instead
of hardcoded rules. Self-awareness here should mean operational self-modeling:
knowing what the system believes, what changed, what is uncertain, and what it
can safely do. This is not a claim about consciousness.

Important correction: do not hardwire Mimir. Use the selected resident memory
backend; today that might be local, Mimir, GBrain, Letheo, or something else.
Also, semantic authority should be model or council driven. Static deterministic
rule matrices are the wrong shape for meaning, even if deterministic code can
enforce contracts and provenance.

The current autonomy proposal code captures useful intent, but it is messy. It
probably needs reset, rewrite, deletion, or simplification before becoming a
base. Do not treat it as production Valkyrie code.

Context hygiene matters. Use bounded cognitive workers or subagents with typed
input and output contracts instead of one giant prompt carrying the whole
product.

Rejected wording: "responsibility" is bad external product language. It sounds
like guardrails, not momentum. Also stop writing vision docs as mobile-hostile
one-line paragraph/list cadence. It reads like a wall of fragments.
